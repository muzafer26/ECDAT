## 1. Architectural Role of the Demo Projection

The demo presentation layer is **strictly downstream** of the frozen ECDAT analytical core. It does not replace, re-implement, or augment the mathematical and logical operations of `product/core/`.

```text
┌────────────────────────────────────────────────────────────────────────┐
│                      FROZEN PRODUCT CORE (product/)                     │
│  [Adapters] → [Evidence] → [Findings] → [Assets] → [Risk] → [Phase 4] │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                         (Immutable Domain Objects)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│              DEMO ANTI-CORRUPTION & PROJECTION BOUNDARY                │
│             (demo/orchestration/transformer.py & models.py)            │
│                                                                        │
│   Separates information into 4 explicit provenance categories:         │
│   1. DIRECT_CORE_OUTPUT          2. CONTROLLED_SCENARIO_CONTEXT        │
│   3. BENCHMARK_GROUND_TRUTH      4. FUTURE_ARCHITECTURE                │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                       (Presentation-Safe DTOs)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   DEMO API & FRONTEND PRESENTATION                     │
│               (demo/backend/app.py & demo/frontend/)                   │
│                                                                        │
│   Pure presentation: renders facts, displays provenance, surfaces      │
│   uncertainties, respects missing values, zero client-side math.       │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. Strict Frontend Boundary Rules

The browser frontend (`app.js`, `index.html`) is a **pure presentation renderer**. Under no circumstances may the frontend:
1. **Calculate risk scores or priority tiers:** Must display `asset.priority_tier` and `asset.risk_category` directly from the API response.
2. **Infer cryptographic roles or primitives:** Must display `asset.role` directly from the Core finding.
3. **Map PQC replacement targets:** Must render `asset.candidate_targets` produced by `PqcTargetMapper`.
4. **Evaluate hybrid combiners:** Must consume `asset.hybrid_candidates` produced by Phase 4B.
5. **Generate migration schedules or milestones:** Must display `migration_summary.milestones` generated by `MigrationScheduler`.
6. **Trigger or resolve review gates:** Must display `migration_summary.review_gates` emitted by the Core.
7. **Invent missing values or fallbacks:** If a property is `null` or empty, the frontend must render the missing state (e.g., `"Not established"`, `"N/A"`, `"Unannotated"`).

## 3. The 4 Provenance Categories

Every data point rendered across any demo screen must originate from exactly one of these four categories:

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 1. DIRECT_CORE_OUTPUT                                                   │
│    Produced directly by frozen product/core/ through real pipeline runs.│
│    Examples: Algorithm identity, operational role, AST location,        │
│    confidence, priority tier, risk cause, classical status, PQC target, │
│    hybrid scheme, DAG milestone, review gate ID.                        │
├─────────────────────────────────────────────────────────────────────────┤
│ 2. CONTROLLED_SCENARIO_CONTEXT                                          │
│    Intentionally supplied by demo scenario configuration metadata.      │
│    Examples: Hosting organization, business system name, component,     │
│    business criticality tier, data lifetime horizon, network exposure.  │
│    Rule: MUST NEVER be represented as discovered by scanner AST.        │
├─────────────────────────────────────────────────────────────────────────┤
│ 3. BENCHMARK_GROUND_TRUTH                                               │
│    Facts known from the benchmark source fixture corpus.                │
│    Examples: TC-01 fixture line 19 initializes 2048-bit modulus.        │
│    Rule: MUST be explicitly distinguished from unevidenced AST findings.│
├─────────────────────────────────────────────────────────────────────────┤
│ 4. FUTURE_ARCHITECTURE                                                  │
│    Planned capabilities, lifecycles, or diff schemas not yet executed.  │
│    Examples: Phase 9 post-migration rescan, cryptographic diff delta.   │
│    Rule: MUST NEVER be presented as completed actions or live scans.    │
└─────────────────────────────────────────────────────────────────────────┘
```

## 4. Projection Mapping: Core Domain Objects to Demo DTOs

| Core Domain Object (`product/core/`) | Projected Demo Model (`demo/orchestration/models.py`) | Provenance Category | Translation Invariants |
| :--- | :--- | :--- | :--- |
| `EvidenceRecord` | `DemoEvidenceSummary` | `DIRECT_CORE_OUTPUT` | Preserves immutable scanner name, version, detection method, AST snippet, line numbers. Paths normalized to relative posix format. |
| `Finding` | `DemoFindingSummary` | `DIRECT_CORE_OUTPUT` | Preserves algorithm identity, observation type, operational role, confidence enum, and interpretation basis. |
| `CryptoAsset` | `DemoAssetSummary` | `DIRECT_CORE_OUTPUT` | Preserves canonical asset ID, family, algorithm, role, key size (or `None`), curve name, and correlation basis. |
| `RiskRecord` | Fields on `DemoAssetSummary` & `DemoRiskSummary` | `DIRECT_CORE_OUTPUT` | Preserves `effective_priority`, `risk_category`, `primary_cause`, `classical_status`, `quantum_exposure_class`, `uncertainty_level`, `observed_facts`, `triggered_rules`, and `missing_facts_and_questions`. |
| `PqcTargetMapping` | Fields on `DemoAssetSummary` & `DemoMigrationSummary` | `DIRECT_CORE_OUTPUT` | Preserves `mapping_status`, `candidate_targets`, `target_details`, `mapping_rationale`, `standards_references`, `agility_assessment`, and `hybrid_candidates`. |
| `MigrationSchedule` | Fields on `DemoMigrationSummary` | `DIRECT_CORE_OUTPUT` | Preserves DAG milestones, prerequisites, schedule status (`ADVISORY`), and agility blockers. |
| `ReviewGate` | Fields on `DemoMigrationSummary` & `DemoAssetSummary` | `DIRECT_CORE_OUTPUT` | Preserves gate ID, trigger reason, missing information, and consequence if unresolved. |
| `CycloneDX CBOM` | `cbom_summary` dictionary | `DIRECT_CORE_OUTPUT` | Preserves spec version (`CycloneDX 1.7`), component count, and dependency edges. |
| Scenario Metadata | Enterprise Context fields on `DemoAssetSummary` | `CONTROLLED_SCENARIO_CONTEXT` | Injected into presentation DTO with explicit provenance label. Missing keys remain `None`. |
| Benchmark Fixture | `benchmark_ground_truth` dict on `DemoAssetSummary` | `BENCHMARK_GROUND_TRUTH` | Encapsulates ground truth facts with `scanner_evidence_status` (`UNEVIDENCED_IN_AST` vs `CONFIRMED_IN_AST`). |

## 5. Missing Information Rendering Specification

When information is not established by the underlying scanner output or scenario context, the presentation layer must apply these deterministic rendering transformations:

| Field Name | When Missing in Core | Prohibited Behavior | Mandatory Demo Rendering |
| :--- | :--- | :--- | :--- |
| `key_size_bits` | Missing from AST | Fabricate 2048 or 256 bits | Display `Not established in AST` + highlight gap in Uncertainty Banner |
| `classical_status` | Cannot evaluate bit length | Fall back to `ACCEPTABLE` | Display `INDETERMINATE` with amber badge |
| `organization` | Empty scenario metadata | Default to "FinTech Enterprise" | Display `Not Specified` |
| `system` | Empty scenario metadata | Default to "Payment Gateway" | Display `Unannotated Service` |
| `agility_level` | Core evaluated None | Force `HARDCODED` without check | Display `NOT_ESTABLISHED` (or evidenced factors) |
| `hybrid_candidates` | Symmetric cipher / empty | Suggest fictitious combiner | Display `None Applicable / Out of Scope for Public-Key Combiners` |
| `review_gates` | Zero active gates | Retain previous scenario gate | Display `No formal review gates active for current scenario run` |
| `milestones` | No milestones generated | Retain previous milestones | Display `No migration milestones generated for current run` |
